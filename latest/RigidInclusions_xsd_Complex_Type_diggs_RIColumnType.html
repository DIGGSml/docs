Element diggs:RIColumnType / diggs:ltpRef
Namespace http://diggsml.org/schemas/3
Annotations
 
The diggs:LoadTransferPlatform that this column is associated with.
It is optional, to allow for columns not associated with an LTP
(trial columns outside a platform, or sacrificial columns that are
not load bearing) and because columns are installed before the
platform is laid over them, so a column record may legitimately be
delivered before its platform exists. A spatial association can be
made, but an explicit association by this property is definitive,
should be used in preference to a spatial comparison, and governs
where the two disagree. The positional test, of the column's
referencePoint against the featureExtent of the platform, remains a
fallback where this element is absent, but it is only an inference:
platform extents may overlap where a structure's platform is drawn
over a residual "remaining area" platform without being punched out
of it, and a column head within centimeters of a shared boundary is
decided by rounding rather than intent. The reference states
membership, asserted by the member, like the inherited
samplingFeatureGroupRef. Given by reference only.

Element diggs:RIColumnType / diggs:riInstallationMethod
Namespace http://diggsml.org/schemas/3
Annotations
 
How the ground was handled as this column was formed: full
displacement, partial displacement or replacement. It is the primary
classifier: a displacement technique generates no spoil and
densifies the surrounding ground, while a replacement technique
removes soil, so the quality-control data a rig can produce and the
acceptance evidence that can be asked for both follow from it. It is
orthogonal to columnType, and constrained against it: columnType
names the technique and this names what that technique does to the
ground, but they are not independent (a continuous flight auger
column cannot be full displacement), so each columnType.xml entry
declares the families it is compatible with through a
conditionalElementXpath on its Occurrence. That check is performed
by dictionary-validation.xsl, not by this schema, because XSD cannot
express a correlation between sibling values; as a consequence,
stating columnType without this element fails dictionary validation,
so in practice the two travel together. The ri prefix marks that
this element is bound to the rigid inclusion list; installation
method is a concept other DIGGS domains will want under their own
vocabularies. Values come from the enumerated list, or "Other: xx",
where xx is a user-defined term whose meaning differs from every
listed value (not a synonym of one).

Element diggs:RIColumnType / diggs:installationSequenceNumber
Namespace http://diggsml.org/schemas/3
Annotations
 
The position this column actually occupied in the installation
order, counting from 1; the as-built counterpart of the planned
order stated by a diggs:DesignProductionSequence. It is recorded
rather than derived, because the actual order is not recoverable
from whenConstructed (optional, thinly populated, and a timestamp
answers when rather than in what order, which matters where several
rigs work concurrently) or from the column's name. Comparing it with
the planned order shows whether a specified sequence was followed,
and it is the as-built side against which a minimum age or minimum
spacing to fresh concrete, specified as a diggs:ClearanceConstraint,
is evaluated.

Element diggs:RIColumnType / diggs:groundSurfaceElevation
Namespace http://diggsml.org/schemas/3
Annotations
 
The elevation of the ground surface, or of the working platform
where one is present, at this column. A rigid inclusion conflates
the drilled hole and the grout column into one sampling feature, and
the column takes precedence for geometry: the centerLine runs from
the column head to the column tip, not from ground level to the tip.
Depths recorded while drilling (measurement-while-drilling data, and
events on the construction activity) are measured from the ground or
platform datum the rig works from, and this property relates the
two; without it, drilling-time depths cannot be placed on the
column. Because it is a position, not a length, it may be stated in
whichever frame it was measured: a one-dimensional position in a
vertical CRS, a one-dimensional position in this column's own linear
referencing system, or a full three-dimensional position. Populate
uomLabels so the unit is readable without resolving the CRS. It
corresponds to the property of the same name on
diggs:AbstractPileType.
