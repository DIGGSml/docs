Element diggs:ClearanceConstraintType / diggs:referenceFeatureType
Namespace http://diggsml.org/schemas/3
Annotations
 
The kind of feature the subject population (the inherited
appliesToFeatureType) must keep clear of. If absent, members of the
subject population clear each other; if it names a different type,
the constraint relates the subject population to that other type.
Use the DIGGS dictionary samplingFeatureTypes.xml, the same one
appliesToFeatureType uses, for the list of values.

Element diggs:ClearanceConstraintType / diggs:temporalOrder
Namespace http://diggsml.org/schemas/3
Annotations
 
Whether minimumElapsedTime is symmetric ("unordered") or directional
("referenceBeforeSubject", "subjectBeforeReference"). If omitted,
the order is unordered, the common case of two peer installations
that need only clear the interval in either order. Values come from
the enumerated list.
Diagram
Type diggs:ClearanceTemporalOrderEnumType
Properties
content simple
minOccurs 0
Facets
enumeration unordered 
The two governing timestamps must be at least minimumElapsedTime apart, in
either order: no two of these within that time of each other.
enumeration referenceBeforeSubject 
The reference feature (or, where referenceFeatureType is absent, an earlier
member of the same subject population) must reach its governing timestamp at
least minimumElapsedTime before the subject does: wait that time after the
reference completes.
enumeration subjectBeforeReference 
The subject must reach its governing timestamp at least minimumElapsedTime
before the reference does; the reverse of referenceBeforeSubject.
