Element diggs:AbstractProgramSpecificationType / diggs:appliesToZone
Namespace http://diggsml.org/schemas/3
Annotations
 
The region this specification applies to, as a plan-view polygon or,
where the region is discontinuous, several polygons. A check, not a
membership test: it does not establish which features the
specification governs, which is asserted only from the realized side
through programSpecificationRef, or from a design that adopts the
specification. Where stated, every feature so established is
expected to have its referencePoint within the region (a node on the
boundary counts as inside); one that does not is a finding, not a
reason to exclude it. Where absent, no spatial check applies.
Independent of the scope of any citing design: a specification
shared across designs, or cited directly by a feature, has no single
design scope to inherit the check from.

Element diggs:AbstractProgramSpecificationType / diggs:appliesToFeatureType
Namespace http://diggsml.org/schemas/3
Annotations
 
The kind of feature this specification applies to, for example
"ri_column" or "load_transfer_platform". The same kind of check as
appliesToZone: every feature established as a member through
programSpecificationRef or an adopting design is expected to be of
this type; one that is not is a finding. Where absent, no type check
applies. The codeSpace is required. For a specification whose
subject is a construction activity, the kind of feature the activity
builds or acts on. Use the DIGGS dictionary samplingFeatureTypes.xml
for the list of values.

Complex Type diggs:AbstractProgramSpecificationType
Namespace http://diggsml.org/schemas/3
Annotations
 
Abstract base type for detailed program specifications that define technical
requirements and acceptance criteria: references to specific standards (for example
ASTM or AASHTO), numerical acceptance criteria, testing methods and frequencies, and
quality control requirements. Unlike designs, specifications are typically
contractual and establish enforceable requirements. basedOnRef cites a more general
specification of the same kind that this one specializes; an acceptance criterion
cites the specification it elaborates through diggs:partOfSpecificationRef instead,
which is a component relationship rather than specialization. basisRef cites the
basis the requirements were derived from.
