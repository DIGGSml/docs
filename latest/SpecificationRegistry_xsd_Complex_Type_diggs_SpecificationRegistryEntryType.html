Element diggs:SpecificationRegistryEntryType / diggs:domain
Namespace http://diggsml.org/schemas/3
Annotations
 
One or more classifications of which domain(s) of
                                practice cite this standard - rigid inclusions, laboratory testing,
                                in-situ testing, sampling, construction, and so on. Coded against
                                def/docs/codes/DIGGS/0.1/specificationDomain.xml.

                                THIS IS WHY ONE REGISTRY CAN SERVE EVERY DOMAIN. A standard cited by
                                more than one domain - ISO 22476-4, say, cited by both rigid
                                inclusion design and in-situ testing - carries one domain element per
                                domain rather than being registered a second time under a different
                                gml:id: the registry holds exactly one canonical entry per real-world
                                standard, never two ids for the same document. domain is what a
                                consumer or a rendering stylesheet filters and browses by, so a
                                registry spanning every domain stays as easy to search as a
                                single-domain one would have been.

                                Mandatory, unlike every other metadata property on this type: an
                                entry with no declared domain cannot be found by a domain-scoped
                                consumer, which defeats the reason domain exists.

Element diggs:SpecificationRegistryEntryType / diggs:registryStatus
Namespace http://diggsml.org/schemas/3
Annotations
 
Lifecycle state of the registered standard. A registry
                                must be able to say that a standard has been withdrawn or superseded
                                WITHOUT deleting its entry, because instances published while it was
                                current still cite it and those citations must keep resolving. ASTM
                                D1194 is the worked example: withdrawn, but present in the
                                historical record of plate load testing.

                                Absent means active; state it explicitly for anything that is
                                not.

Current and in force. The default reading when registryStatus is

enumeration superseded 
Replaced by a later standard, which should be named in

enumeration withdrawn 
Withdrawn by its publisher without a direct replacement. Retained

it.

Element diggs:SpecificationRegistryEntryType / diggs:supersededByRef
Namespace http://diggsml.org/schemas/3
Annotations
 
For an entry whose registryStatus is superseded or
                                withdrawn, a reference to the Specification that replaces it -
                                normally one registered elsewhere in the same registry. Lets a
                                consumer follow a historical citation forward to the current
                                standard.

                                Points at the replacement diggs:Specification, not at its
                                SpecificationRegistryEntry, so that following this reference yields
                                the same kind of object as following a governingStandard. The
                                superseding entry must appear EARLIER in the registry than the entry
                                that cites it; DIGGS forbids forward references.

Element diggs:SpecificationRegistryEntryType / diggs:occurrences
Namespace http://diggsml.org/schemas/3
Annotations
 
One or more diggs:Occurrence objects declaring where the
                                registered Specification may legitimately be cited:
                                sourceElementXpath gives the element that may hold a reference to
                                it, and the optional conditionalElementXpath gives an element (and
                                optionally a value) that must be present for the citation to be
                                valid.

                                THIS IS THE DOMAIN CHECK. Resolving an xlink:href proves only that
                                the target exists and is a diggs:Specification; it cannot tell a
                                rigid inclusion design basis from a laboratory sample preparation
                                method, since both are Specifications. These declarations are what
                                make the distinction machine-checkable, and they are read from the
                                target's entry rather than configured into the validator - so the
                                validator stays generic and vocabulary-independent, exactly as
                                dictionary-validation.xsl already is for code lists.

                                A validator that has resolved an href to a Specification inside a
                                registry reaches these by one step up:
                                ancestor::diggs:SpecificationRegistryEntry/diggs:occurrences.

                                An entry with no occurrences declares no restriction, and its
                                Specification may be cited anywhere one is permitted. Prefer stating
                                them: an unbounded entry is the registry equivalent of an
                                unconditioned dictionary Occurrence, and those have been a recurring
                                source of misuse.

                                Reuses diggs:OccurrenceArrayPropertyType from Dictionary_diggs.xsd
                                without modification. The shape is not dictionary-specific - it is a
                                general "this term is permitted here, conditionally on that" - and
                                reusing it rather than inventing a parallel form is what lets one
                                validator serve both mechanisms.

Complex Type diggs:SpecificationRegistryEntryType
Namespace http://diggsml.org/schemas/3
Annotations
 
Type for one registration. Extends diggs:AbstractObjectType, the standard
                base for DIGGS component objects, since an entry has no independent existence
                outside the registry that contains it.

                Holds the registered diggs:Specification by value, followed by the registration
                metadata. Every metadata property is optional except the Specification itself and
                its domain classification: an entry that registers nothing is meaningless, an entry
                with no declared domain cannot be found by a domain-scoped consumer and defeats the
                reason domain exists, but an entry that declares no lifecycle, authority or scope
                beyond that is merely unrestricted.
