Element diggs:DesignMeasurementType / diggs:measurementLocation
Namespace http://diggsml.org/schemas/3
Annotations
 
The planned location of the measurement: most often a
diggs:LinearExtent for the planned depth or depth interval in the
linear referencing system of samplingFeatureDesignRef, a
diggs:PointLocation for a single test position or instrument point,
or a diggs:MultiPointLocation for several positions served by one
provision. A planned measurement has no result coverage to carry its
position, so the position is stated here. It complements the
testingDensity choice: a density states spacing without committing
to positions, this states the positions, and both together are
meaningful where a spacing has been resolved into a schedule.
Normally omit it where the measurement is on a planned sample, whose
own position (diggs:DesignSampleType/samplingLocation or
sampleScope/samplingPosition) carries the depth. Omit it also where
the measurement applies to the whole of the referenced feature, as
an axial load test applies to a whole column; absence means the
provision is not positioned, not that its position is unknown.

Element diggs:DesignMeasurementType / diggs:plannedProcedure
Namespace http://diggsml.org/schemas/3
Annotations
 
The procedure the measurement is planned to be carried out with, as
the same procedure object a realized measurement carries in its
procedure property, for example a diggs:PlateLoadTest or a
diggs:StaticLoadTest, inline or by reference. It states the planned
values of the procedure (plate size, bedding, reference system,
maximum stress, planned increments with stress and hold) in the
structure the realized procedure uses, so planned and realized
values compare field for field. It states intent; a requirement the
realized measurement must meet is a criterion. Contrast
measurementMethod, which cites the standard to follow. Repeat for
each procedure.

Element diggs:DesignMeasurementType / diggs:testedFraction
Namespace http://diggsml.org/schemas/3
Annotations
 
The proportion of a planned population of elements that is to be
tested, where a testing provision is scoped to a population rather
than to named elements, for example "5 percent of production rigid
inclusions". Typically uom="%". It answers how many, not how often:
it is distinct from readingFrequency and from the testingDensity
choice. samplingFeatureDesignRef names which features a provision
governs; this element states what share of that population is
tested, and both are normally needed.

Element diggs:DesignMeasurementType / diggs:testLoadPercentDesignLoad
Namespace http://diggsml.org/schemas/3
Annotations
 
The maximum load a planned load test is to reach, as a percentage of
the design working load of the element tested. Typically uom="%". It
is a ratio because test requirements are written that way and the
absolute value differs per element, which lets one population-scoped
provision govern a zone. Where the tested element is not the element
the design load acts on, such as a column loaded through a plate in
a test of a platform design pressure, state the planned maximum
stress on the planned procedure instead. It carries the value only;
state any derivation in a remark.
